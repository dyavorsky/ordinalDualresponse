The model in miniature: a first ordinal dual-response example

This vignette walks through the smallest interesting version of the ordinal dual-response model: one attribute, homogeneous preferences, and a three-point purchase-likelihood scale (“unlikely / unsure / likely”). It mirrors the worked example in the accompanying paper.

The behavioral model in four lines

In each task a consumer sees \(J\) inside goods with utilities \(u_j = V_j + \eta_j\), \(\eta_j \sim \text{Gumbel}(0,1)\), picks the best one (the forced choice), and then evaluates buying it against an outside good whose shock \(\eta_0\) she has not resolved. Under Model A she reports the probability \(F(u^*)\) in bins; under Model B she grades the realized comparison \(u^* - \eta_0\). Both give a joint likelihood of MNL \(\times\) a cumulative-link ordinal model driven by the task’s inclusive value \(\bar\mu = \ln \sum_j e^{V_j}\).

Two consumers, opposite reports, identical choices

Give two consumers the same taste (\(\beta = 1\)) and the same within-task spread of the attribute, but different levels:

library(ordinalDR)
beta <- 1
cut <- c(0, 2)                       # W = 3: "unlikely" | "unsure" | "likely"
x1 <- c(2, 1)                        # attractive task
x2 <- c(-1, -2)                      # unattractive task

mnl <- function(x) exp(beta * x) / sum(exp(beta * x))
rbind(task1 = mnl(x1), task2 = mnl(x2))
#>            [,1]      [,2]
#> task1 0.7310586 0.2689414
#> task2 0.7310586 0.2689414

The forced-choice probabilities are identical — the MNL reads only differences. The ordinal stage reads levels:

mubar <- c(log(sum(exp(beta * x1))), log(sum(exp(beta * x2))))
probs <- function(mu, model) diff(c(0, if (model == "B") plogis(cut - mu)
                                    else exp(-exp(-(cut - mu))), 1))
rbind(task1_B = probs(mubar[1], "B"), task2_B = probs(mubar[2], "B"),
      task1_A = probs(mubar[1], "A"), task2_A = probs(mubar[2], "A"))
#>                 [,1]      [,2]       [,3]
#> task1_B 9.003057e-02 0.3322882 0.57768120
#> task2_B 6.652410e-01 0.2709986 0.06376045
#> task1_A 4.077922e-05 0.2546056 0.74535362
#> task2_A 6.045840e-01 0.3295806 0.06583548

Near mirror images. All demand information flows through the second response.

Simulate the two-consumer world at scale and estimate

dr_simulate() draws raw utilities and applies the reporting rules — the estimation below therefore validates the derivation, not just the code.

n <- 4000
X <- matrix(rep(c(x1, x2), n / 2), ncol = 1)
des <- list(X = X, n_tasks = n, J = 2, P = 1)
dat <- dr_simulate(des, matrix(beta, 1, 1), cut, model = "B", seed = 7)
fit <- dr_mle(dat)
fit
#> ordinal dual-response MLE (model B, W = 3)
#>    estimate     se
#> b1   0.9783 0.0208
#> c1   0.0248 0.0397
#> c2   1.9488 0.0436
#> logLik -5771.30 | convergence 0 | max|grad| 1.0e-03 | min eig(H) 518.0

The MLE recovers \(\beta = 1\) and the cut points \((0, 2)\) from nothing but choices and three-point reports. The identification requirement — no attribute direction constant across all inside goods — holds here because the two tasks sit at different levels:

dr_rank_check(des$X)
#> $rank
#> [1] 2
#> 
#> $required
#> [1] 2
#> 
#> $pass
#> [1] TRUE
